## 每次如何处理

1. **先看原件。** 图片实际打开；录屏记录实际观看范围、时间点及尺寸；链接实际访问后才说已读。不能访问或缺少画面就登记缺口，不靠转述补造证据。
2. **分开四类内容。** 用户明确要求、设计师意见、可借鉴点、未批准建议分别记录；设计师认可不等于用户批准，用户未回应不等于同意。
3. **落到任务和状态。** 标出适用页面、触发操作、解决的问题、建议改变及不照搬的部分；按功能分区、信息层级、主要操作、内容承载、状态、动效、中文排版归类。
4. **给可核对判据。** 用真实视口、具体操作、可观察结果描述；截图只能证明可见外观，不能代替键盘、存储、模型或业务验证。
5. **回传统筹。** 附文件、优先建议、依据、冲突、检查结果与未验项。由统筹统一整合；本任务完成本轮后停止，等待下一次投喂，不自行派活或创建定时任务。
