Use case: ui-mockup
Create a realistic, production-quality Chinese desktop web app UI, full primary screen, high-fidelity design concept, not a marketing page. Direction name for the brief only: "清爽引导页". Do not print this direction name or an option number on the image.
Target dimensions: 1440 x 900. Current date: 2026-08-28, Asia/Shanghai. No date needs to be displayed.
Product: "抖音做了不出单怎么办", a calm business decision assistant for ordinary Chinese merchants. The full first screen of a three-independent-page workflow is required, not a feature inventory. The merchant can begin with one sentence OR a file; no long questionnaire. Later pages compare choices then deliver the chosen action. This screen must not diagnose or recommend a business path.
Visual direction: fresh, unusually clear and inviting, true white background #FFFFFF, forest green #26644E, dark gray-green text #202D27, very pale green #F3F8F4 only inside the optional material strip, hairline #DAE3DD. Flat, no shadows, no gradients. Chinese sans serif, relaxed but precise type and spacing, practical code-native native HTML controls, subtle 6–8px control corners. Body16–18px, helpers>=12px, touch targets>=44px.
Layout strategy meaningfully different from a two-column form: a centered, open, single reading flow about900px wide, with a narrow left margin alignment line and a full-width input. No enclosing application card, no large bordered sections. Quiet header product name left "抖音做了不出单怎么办"; right aligned three-step nav "说清问题" current in green, "看清选择" muted, "拿去执行" muted. Under header, generous whitespace and modest heading "最近做抖音，哪件事最让你头疼？", about32px, not marketing hero-size. Supporting text "一句话也可以，不用先懂数据".
Then label "用自己的话描述问题", wide shallow textarea about135px tall with subtle border and placeholder "比如：有人咨询，后来没下文". Underneath, a compact row with "试试这样说" and two quiet plain text buttons "有人看，但没人买", "说不清卡在哪里".
After generous vertical spacing, an optional material handoff band on the same canvas with very pale green wash, not a card nested in a card: left a small purposeful outline paperclip/upload icon, text "交一份手头材料", helper "有相关截图或报表，也可以一起发来，不用提前整理"; right an outlined button "选择文件"; below in the same band "也可以拖入文件，或粘贴截图". Clearly communicates both dragdrop and click. Below the band, compact readable text "PNG / JPG / WebP / TXT / CSV / JSON · 最多6份，每份5MiB，总计20MiB".
At the end of this flow, a divider and action row: explanation left "先说一句，或交一份材料，就能开始。" and a green "整理一下" button right, shown disabled for the empty input state. Bottom footer small "材料仅在本机处理；图片内容仍需核对。" and "界面示意 · 尚未处理材料".
Fit everything naturally with wide readable whitespace and crisp exact Chinese text. No fake uploads, no actual processing status or made-up merchant data, no chart, no dashboard, no diagnosis, no score, no probabilities, no chatbox, no login, no avatar, no unsupported features. Do not include browser chrome, device frames, sidebar, headings above the main heading, pills/badges, card grids, illustrations, decorative imagery, or marketing promises. All UI text/buttons/fields are intended to be real HTML, not raster controls in implementation. Design full first-page empty state only, with reusable navigation/forms/primary-control language that can extend to later decision and action pages.
