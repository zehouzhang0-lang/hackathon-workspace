## 每个Agent开工前必须做

1. 从可用工具列表发现21st与React Bits/shadcn MCP，不仅搜索插件名称。
2. 21st执行一次免费元信息检索，例如`file upload`、`tabs`或`accordion`，限制少量结果；记录调用名、查询、是否成功，不记录密钥。
3. React Bits先列注册表，确认`@react-bits`，再搜索`FadeContent`等相关组件；返回错误不能写“已接通”。当前连接若仍报NOT_CONFIGURED，先重载该MCP再验证。
4. 根据页面需要记录候选资源及用途；实际使用必须服从同一母版、原生HTML技术约束和功能需要，不因为看见炫酷组件就换主题或堆动效。
5. 将结果写入自己的QA记录。源码检索、组件安装、页面集成、视觉验收是四件不同的事，分别记录。

工具缺失、认证失败或注册表缺失时：报告准确错误给统筹，由统筹统一补连接/重载。不得三个对话同时编辑用户配置，不得要求把密钥贴入聊天、README或环境日志。可继续做不依赖该资源的内容检查，但不能伪报资源已用上。

## 连接配置的共享规则

Codex的同一宿主可共享本机MCP配置；STDIO配置的`cwd`决定启动进程的工作目录。注册服务器和注册组件来源要分别验证。[OpenAI官方MCP说明](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

21st使用用户已有的本机连接与安全凭据；不新建重复连接、不将配置整体复制进项目。搜索元信息免费，读取组件源码可能消耗配额或付费；不要因“接好MCP”就购买资源或批量下载。

React Bits通过shadcn MCP读取注册表。统筹可复用本机独立设计资源目录中的配置，不为了检索而初始化React应用。注册表示例如下，**只是配置片段，不让页面Agent覆盖现有文件**：

```json
{
  "registries": {
    "@react-bits": "https://reactbits.dev/r/{name}.json"
  }
}
```

项目注册表来自`components.json`；Codex客户端的连接设置与Claude Code不同，不照抄附件中的`--client claude`命令。[shadcn官方MCP说明](https://ui.shadcn.com/docs/mcp)

已经安装并可调用的工具优先复用，不执行`npx ...@latest`反复安装、清缓存或升级。换设备由统筹解析那台电脑的实际运行路径与权限，不能照搬本机绝对路径或假设Git同步了凭据。

## 在统一视觉母版中怎样用

- Agent1：寻找简洁上传、输入、材料预览与状态反馈参考。
- Agent2：寻找路径比较、分层披露、证据展开、图示与选中反馈参考。
- Agent3：寻找文案取用、步骤清单、轻量反馈和保存状态参考。
- 统筹统一选组件语言与动效规则；主题、全局token和公共控件仍由共享目录提供。

React Bits主要是React组件来源，部分含GSAP等依赖。MCP接通不代表这些代码能直接贴进原生HTML：先检查许可证、依赖和兼容性；能保持效果与语义时在共同规范下实现，必须引入依赖/改变技术方案时先报统筹，不各自换栈。MCP用于开发资源，不会替产品接通OCR、抖音数据或MoneyAI。

本轮只接入与验证、准备prompt；尚未选定或集成任何组件，也没有生成三页视觉母版。
