# 第一页：本轮问题与资料收集

更新：2026-08-28。**交互主流程已由用户确认；视觉方案与技术实现尚未确认。**

本文记录逐项讨论后的第一页约定。此前三张视觉稿均未获认可，不作为实现目标。用户随后授权睡前整理第二、第三页的待讨论方案，供明早回应；这不代表批准后两页，也不授权开始视觉生成或应用实现。

## 1. 页面目标与门槛

让商家用一句自己的话、一份手头材料，或两者一起，开始整理本轮问题与可用依据。

- 不要求先建完整商家档案，不列出一长串必填资料。
- 系统先承担识别、整理和核对口径的工作，再补关键缺口。
- 不把长问卷拆成许多轮聊天。首轮最多主动补问一项，允许“不知道”和“暂时跳过”。
- 数据不足时，保留未知并说明能分析的范围；不编造经营指标或强行形成完整诊断。

## 2. 首屏：问题描述与资料上传

### 问题描述区

描述区常驻在首屏，与上传区共同构成主要操作区域；建议放在上传区上方，具体视觉布局待定。

- 标题参考：“最近做抖音，哪件事最让你头疼？”
- 提示参考：“按自己的话说，一句话也可以。”
- 示例参考：“直播有人看，也有人问价，但最后没几个人下单，不知道该改哪里。”
- 可提供少量可点击、可修改的参考表达，例如“有人看，但没人买”“有人咨询，后来没下文”“做了一段时间，说不清卡在哪里”。

参考表达只帮助起笔，不是逐项问题，不自动替商家填写经营数字，也不预设不出单的原因。原先“没有资料，先说说情况”的入口并入此区，避免重复入口。

### 资料上传区

- 交互目标：支持点击选择、拖入文件、粘贴截图。
- 提示参考：“有相关截图或报表，也可以一起发来，不用提前整理。”
- 先描述、先上传均可；提供其中一种即可开始整理。
- 可继续添加、替换或删除材料，不要求每个附件另填一套说明。
- 具体文件格式、数量、大小、解析器及处理位置尚待技术确认，不把计划支持写成已实现能力。

## 3. 同页处理与反馈

### 收到材料

原地展示材料预览与真实处理状态，例如已接收、正在识别、正在整理、部分内容未读清。状态必须对应实际工作，不使用假进度或假成功提示。

处理失败时保留原件，说明如何替换、重试或手动补充。实际存储与保留方式待确认。

### 整理结果

在同一页展开一份简短、可纠正的整理结果，不新增独立确认页：

1. **本轮想解决什么**：根据商家描述和材料明确关注范围，不把商家的猜测当作已证实的原因。
2. **从材料里读到了什么**：只显示相关信息；可定位原始截图、表格或文本来源。商家可以纠错，不必逐字段确认所有内容。
3. **有什么影响判断的缺口**：优先处理会改变后续判断的关键歧义。首轮最多主动补问一项；跳过后仍保留限制，不把未知改成确定值。

整理应产生实际价值，例如识别“描述针对单场直播，但资料是全店整月流水”的范围不一致，避免把两份数据直接拼成转化结论。

### 页面结束

- 主操作：“就看这个问题”。
- 修改入口：“我想补充”。
- 确认的是本轮分析问题与可用依据，不代表商家逐项核实了所有提取值，也不代表已证明原因。
- 第一个页面到此结束。原因判断、决策路径和行动方案留到第二页；其方向已在[第二页约定](PAGE_TWO_DISCUSSION.md)补充，具体布局、实现及第三页仍待确认。

## 4. 数据处理原则

商家描述说明他关心什么，材料为判断提供依据。系统从两者中提取时间、商品、指标和已尝试动作；未提供的信息暂留未知，不自动展开成必填字段。

- 原件、提取结果、商家自述、派生计算、公共参考和情景假设分别保留性质与来源。
- 变量需要保留单位、统计对象、时间、渠道、统计口径及来源位置；具体数据结构待实现阶段确定。
- 未提供、不知道、不适用和真实的零值必须区分。
- 时间、对象或渠道不匹配的数据不能直接拼接计算；识别冲突不能静默覆盖。
- 修改描述、替换或删除材料后，相应整理结果需要更新或标为待重新整理，不能继续沿用旧依据。

## 5. 待执行的检查

以下是从已确认交互推导的验收方向，**均未执行**，不是功能通过记录：

- 只写一句话、只交一份材料、同时提供两者，均能开始相应整理，不被完整档案拦住。
- 示例提示不强制选择，不生成用户没有确认的经营数字。
- 能从材料直接读取的信息不重复询问；关键补问不演变成长问卷。
- 每个展示的提取项能定位来源；识别失败、冲突和未知可见。
- 跳过关键缺口后，不生成依赖该缺口的确定性结论。
- 修改或删除输入后，不保留失效的提取结果作为当前依据。
- 问题确认与补充修改均在同页完成，不要求逐字段签字确认。
