## 2. 不依赖视觉选择的实施顺序

## 5. 必须可复现的验收步骤

以下全部为**待执行**；记录初始种子、操作序列、期望与实得、错误码、版本前后值，失败修复后重跑，不先填写“通过”。

### 存储失败、草稿与恢复（D02、D12、D14）

1. 在有合成记录的会话中分别注入打开/读取失败；`loadSession` 应报错，不创建假空会话、不套旧答案。解除失败后重试，应仍能读回原记录。
2. 在写入请求已返回、事务尚未完成时强制 abort；用 `MATERIAL_ADD` 和含两份记录的 `FEEDBACK_SAVE` 各测一次。状态、Blob、两份反馈相关记录和去重依据须整体回滚；刷新无半条正式记录。
3. 页面内存草稿保持原文，提示未保存；保存失败不能自动导航或允许依赖该反馈的 `ROUND_START`，也不能显示“MoneyAI 已记住”。已有文本仍可手动取用。
4. 真实提交后丢弃响应，客户端应显示结果待确认；重读或用同一 `commandId` 重试。只能存在一份已提交业务记录，不能把响应超时解释为必然未写入。
5. 解除注入后再保存、刷新并重开同源测试宿主，逐项比对字段和 Blob 字节；事务完成才称“本地保存”，实际读回才称“已读取本地记录”。
6. 生成分析/执行稿时注入受控失败，并用实际非法输入验证校验失败；不得自动换成旧参考答案或伪称已生成/保存。保留当前草稿和合法历史，重试后仍校验输入版本。

### 幂等、并发和迟到结果（D04、D12、D14）

1. 同一 `commandId`、同一载荷连续点击、超时重试及刷新后重试，不增加第二份记录/轮次/事件或重复版本；同 ID 换载荷须拒绝。旧 `expectedRevision` 的已完成命令重试不能误作新冲突写入。
2. 两标签读取同一 revision，各自编辑；A 提交成功，B 用旧 revision 提交须 `conflict`，保留 B 草稿并提示重读，不最后写者覆盖。订阅通知在提交后到达，页面重读当前版本。
3. 暂停解析/整理/分析响应，随后改资料、删除该材料或开新轮；放行旧响应，应拒绝过期 round/inputVersion/材料引用，不能恢复已删除原件或覆盖新结果。
4. 从补问 unused 的独立会话提交 `QUESTION_SET`：调用方生成 `commandId`，首次 payload 使用 `questionId:null,status:"asked"` 及正文/来源。成功后从返回 state 读取真实 questionId；只产生一次提问事件、一次 revision 变化，inputVersion 不因发问增加。分别注入提交前 abort 和提交后响应丢失：前者读回仍 unused，后者读回仅有同一道题；同 commandId/原 payload（仍为 null ID）重试不得另分配问题、事件或额度。同 ID 改正文、当前题仍asked时换新commandId再问、回答携带未存题ID均拒绝；回答/跳过后可依次问至多3题。补测第4题拒绝、旧答案主动修订、额度刷新/跨页保持与旧单问只读兼容。
5. 使用成功读回的 questionId，在独立场景分别回答、回答未知、跳过及主动补充；答案保存重试沿用各动作的 commandId。刷新、跨页、同轮纠错均不重发额度；有剩余额度且无当前asked时可继续至同轮最多3题。正文/答案/未知来源保持关联，只有明确新 round 才重发预算；内容变化与纯状态变化的 inputVersion 按细则分别核对。
6. 分别暂停 MATERIAL_RESULT_SET 与 ORGANIZATION_SET：记录启动 round/inputVersion/材料版本，带未解析缺口完成确认及有限分析后才放行实质结果。因确认/分析导致 revision 改变时先测 conflict，再重读并只更新 expectedRevision；成功接收须同事务使 inputVersion 恰加一次、撤销确认并使旧分析失效。另用有有效选择/产物的合成输入重复，验证选择归档清空、产物标 stale、原执行引用不变；提交前 abort 则全部不变。
7. 在上述投影返回前保留旧快照生成的分析/产物草稿；投影推进 inputVersion 后即使用最新 revision 提交，也须拒绝 stale_input，不允许给旧草稿换版本号。分别对两类投影比较确认前且无有效下游、确认后仅状态、完全无变化、实质事实/范围/约束/重要缺口变化；前两类不加 inputVersion，完全无变化也不加 revision，实质变化按当前是否已确认/有有效下游处理。
8. 检查解析/生成草稿的新对象 ID 与内部引用在保存后均可解析，已有事实/来源 ID 不被错误重分配；重放同命令不能换一套持久 ID。导出动作的 commandId/exportId 由调用方生成并校验：同次操作补记日志沿用原 ID 且不重新下载，用户明确再次导出才使用新 exportId。含业务原文、重复或越界引用的非法 ID/结构须拒绝。

### Blob 持久、删除、替换与重置（D02、D16）

1. 通过共享隔离测试入口准备已知字节的旧图片兼容性fixture（不重新开放产品新图片入口），提交后刷新/重开，通过 `getMaterialBlob` 比较内容与预览；元数据存在不能替代原件实际读回，不用文件名证明内容相同。
2. 删除材料后刷新、查旧来源和历史：原件读取为 null，旧引用明确“原件已移除”，历史无可恢复该原件的 Blob/base64 副本。迟到解析仍不得把它恢复。
3. 替换操作先取消，再注入写失败，旧 Blob/状态均应完整；成功替换才改变输入版本并失效下游。检查旧 Blob 没有成为孤儿，历史不得把新原件冒充旧原件。
4. 重置前取消确认应无改动；明确确认后只清本会话数据及 Blob。放置同源其他应用/会话的测试哨兵，验证它们不受影响；失败重置不可显示已清空。
5. 文件去重与命令幂等分别验证：同名不同内容、同内容改名、同批重复、部分超限、替换容量差值；依细则逐项接受/拒绝，不丢已成功材料。

### 输入、选路与跨轮失效（D12、D13）

1. 用共享命令依次建立已确认输入、分析、选择、产物和主动反馈；再改一项事实。确认撤销，相关分析/产物标旧，选择归档并清空，原执行引用不变；旧结果不能用于当前选路/导出。
2. 同 inputVersion 换 analysisId、同分析改选另一条路分别重测；旧选择与依赖产物归档/失效，不迁移执行记录。重复选择同一有效路径不制造假版本。
3. 未保存 feedbackId 启动新轮应拒绝；已保存反馈重复 `ROUND_START`（包括不同 commandId、双标签）只能建一轮。验证 round/inputVersion 推进、旧快照保留、当前分析/选择清空及补问预算重置。
4. 再保存新反馈并进入第三轮，证明轮次不是固定 1/2；未改变的问题可依契约保持确认，新增冲突回第一页。上轮临时限制仅留历史，本轮保持未知或使用主动更新的来源。
5. 不填执行/观察保持 unknown；“全部做了但变差、时间未填”应保存 done/worse/null，不改成 declined、自动回滚或成功归因。反馈时间、保存时间、执行时间不能互相代填。

### 导航守卫与恢复（D15）

1. 无确认输入直达 decisions、无有效选择直达 action；提供短引导，不默认选择第一条，不自动载入合成案例。正常选择必须提交成功才进入下一页。
2. 留内存脏草稿，分别点页头、页内返回：保存成功再离开；保存失败停留并可重试；明确放弃才丢草稿。取消操作应留在原处，不记录未执行或拒绝方案。
3. 测真实刷新/关闭的标准 `beforeunload` 提示及浏览器前进/后退；浏览器能否弹提示须实测，不能承诺异步离开保存。恢复后重读当前 revision，读取失败如实报错。
