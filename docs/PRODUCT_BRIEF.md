## 1. 产品定位

面向已经运营抖音、但成交不理想的小微商家：输入账号定位、内容、商品及咨询成交数据，提出有证据支持的成交问题假设，给出优先行动，并在下一次诊断中结合历史动作与新数据复查。

工作名称：**抖音成交诊断 Agent**。路演可用“AI 增长诊所”帮助理解，但不暗示诊断结论必然正确。

当前优先题目：**第 5 题——抖音做了不出单，怎么办**。编号及题目来自用户提供的材料，完整官方题目说明尚待确认。

首版只解决一个平台上的一个具体经营问题。跨平台拓展、全功能运营后台和自动获客暂不进入范围。

## 3. 产品范围：六项能力

| 能力 | 首版要完成的事 | 不夸大的边界 |
| --- | --- | --- |
| 经营者输入 | 收集行业、产品、客单价、账号定位、近 7 条视频资料及咨询成交情况 | 手动填写或粘贴；仅提供账号链接不能被当成已读取后台数据 |
| 五维诊断 | 检查人群定位、内容留存、流量质量、产品报价、成交承接 | 只分析已提供的资料，缺少证据的维度显示“待补充” |
| 问题排序 | 列出最多 3 个优先验证的问题 | 以本案例的证据、影响路径和行动成本排序；不强行凑数，不编造概率 |
| 行动方案 | 每个问题对应一个具体动作及观察方法 | 内容选题服务于某个问题，不单独扩成大规模内容生成器 |
| 商家历史记忆 | 保存商家资料、诊断、行动及执行状态；拟使用 MoneyAI 支持的方式实现 | 接口、授权、跨会话保存方式尚未核验；不能把本地存储说成 MoneyAI 记忆 |
| 二次复诊 | 对照上次问题、已执行动作和新数据，给出继续、调整或补证建议 | 展示变化与不确定性，不把短期相关变化归因于产品效果 |

明确不做：抖音平台 API 接入、自动采集后台数据、自动发布、自动投放、全功能运营后台、成交结果承诺。

## 4. 输入与证据约定

首个 Demo 只选**一个具体行业、一个商家案例**，行业待用户或命题企业确认。优先使用获准使用的脱敏真实资料；没有真实资料时，合成案例必须在输入页、报告和路演中明确标为虚构演示。

| 输入组 | 建议内容 | 处理约定 |
| --- | --- | --- |
| 商家档案 | 商家标识、行业、目标客户、服务地区、账号定位 | 不要求手机号、客户姓名等个人身份信息 |
| 产品与承接 | 产品、价格、购买理由、购买入口、咨询和履约方式 | 价格“贵或便宜”需要客户反馈或其他证据，不能仅凭数字判断 |
| 视频资料 | 最多近期 7 条的标识、发布时间、时长、脚本/字幕、主要表达与购买引导 | 链接仅作参考；未查看的视频画面和声音不作为判断依据；不足 7 条可继续但标记样本有限 |
| 视频表现 | 播放、留存或完播、互动、点击等商家能提供的指标 | 每项记录来源、单位、统计区间与采集时间；没有的数据留空，不填 0 |
| 流量与成交 | 自然/付费来源、投放变化、咨询人数、咨询后成交人数、可用的匿名反馈 | 明确数据能否关联到同一批视频或同一批用户，不强行拼接漏斗 |
| 已执行动作 | 做过什么、何时开始、完成状态、执行范围 | 未完成的动作不能被判定为“无效” |

计算比率前确认分子与分母对应同一对象、时间窗、统计口径，且分母大于 0。例如，只有在来源匹配时才计算“咨询后成交人数 ÷ 有效咨询人数”。播放次数与咨询人数不能未经说明就拼成用户转化率。分母为 0 或缺失时显示“无法计算”。

不同发布时间的视频要记录数据成熟时间；复诊需提示观察时长、自然/付费流量、价格、投放等变化。没有可比条件时只分别展示数据，不下增长或改善结论。

## 5. 诊断报告约定

每个优先问题至少展示：

1. **观察**：输入里具体出现了什么。
2. **问题假设**：它可能在哪个环节影响成交，避免把假设写成已证实原因。
3. **证据引用**：对应的视频标识、输入字段或匿名反馈；区分商家自述与可核对的数据。
4. **证据缺口**：还不知道什么、下一步要补什么。
5. **优先动作**：一个可以立即执行的改动，包括改哪里、改成什么、谁执行。
6. **观察方式**：后续收集什么指标、何时复查；没有基线时先建立基线。

五维检查使用“有观察支持 / 待补充 / 暂未发现明显问题”等说明，并展示依据。首版不使用没有标定依据的百分制健康分、行业排名或虚构的成交提升预测。

可视化重点是证据卡、可解释的问题顺序、动作清单和前后对照表。只有数据支持时才画实际指标图，不为了图形完整而补造数据。

## 6. 记忆与复诊

拟保存的最小档案为：商家资料、带时间与来源的数据快照、历史诊断及证据、建议动作、用户确认的执行状态、复诊结果。商家自述、模型判断、已验证观察分别记录；历史记录不能被悄悄覆盖。

复诊时先读取上次记录，再询问执行情况和新数据，最终回答三个问题：**上次优先改什么；现在观察到什么变化；下一步为什么继续或调整。** 同时列出不可比因素和证据不足项。

顾问表达保持简明、务实：记住用户确认的目标和沟通偏好，复诊时引用上次的具体动作，先给一件优先要做的事。“人格化跟进”体现在这种连续的沟通中，不能替代证据，也不等于自动定时联系商家。

MoneyAI 的角色是待验证的实现要求，而不是已证实的接口能力。开工后先做最小验证：为商家 A 保存一条带来源的历史动作，结束会话后重新读取并用于复诊，再确认商家 B 不会读到 A 的记录。真实接入还需核实授权、保留范围、修改/删除方式、调用限制与失败行为。

若平台能力不足，演示替代方案必须符合比赛规则，并显式说明使用的实际存储方式；不能以拼接提示词或本地缓存冒充已验证的 MoneyAI 长期记忆。自动定时跟进不在首版范围，首版由商家主动发起复诊。

## 7. 路演表达

建议主线：**一个老板的经营问题 → 有依据的第一优先动作 → 记录执行 → 带着历史复诊**。五分钟只是待排练的演示目标，不是当前已验证的响应速度。

建议产品表达：

> 我们希望帮助已经在做抖音的小微商家，把零散数据整理成有依据的行动顺序。系统记录上次诊断和实际执行的动作，在新数据到来时继续复查，让每次调整都有记录可追溯。

对主办方：用实际演示证明 MoneyAI 如何保存并读取经营档案，以及这些历史信息怎样改变本次建议。

对投资人：说明先验证一个明确场景中的使用价值，再考虑付费意愿和其他平台。**目前未验证需求规模、付费意愿或经营效果。**

避免“普通 AI 都没有记忆”“首版已经验证需求”“用了就能出单”等表述；用可展示的档案、证据和复诊过程说明差异。
