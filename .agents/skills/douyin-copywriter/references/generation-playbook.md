# 文案生成方法库

只读取当前任务对应章节。模板用于选择策略，不是必须原样套用的句子。

## 共通创作骨架

先确定四个要素：

1. 受众此刻的场景或问题；
2. 这条内容提供的单一核心价值；
3. 支撑价值的事实、方法、例子或过程；
4. 看完后希望用户做的一个动作。

优先采用“具体场景或问题 → 清晰承诺 → 证据或步骤 → 收获或转折 → 单一行动”的自然链路。标题、开场和结尾应能从同一条链路中推导出来。

## 标题文案

### 标题策略库

| 类型 | 适用内容 | 可改写骨架 | 约束 |
|---|---|---|---|
| 数字型 | 教程、清单、经验总结 | `掌握这【数量】点，解决【具体问题】` | 数量必须与正文一致 |
| 疑问型 | 科普、误区、问题解释 | `为什么【常见现象】？关键在【范围提示】` | 正文必须回答问题 |
| 悬念型 | 揭秘、反转、认知差 | `原来【主题】的关键不是【旧认知】` | 留信息差，不故意隐瞒核心价值 |
| 感叹型 | 明显效果、体验分享 | `没想到【具体方法】能让【结果】` | 情绪强度要与素材匹配 |
| 痛点型 | 解决方案、避坑 | `总在【失败场景】？先检查这【数量】处` | 不制造羞辱或焦虑 |
| 利益型 | 方法、效率、结果导向 | `用【方法】把【任务】做得更【可感知结果】` | 不写无法证明的效果倍数 |
| 反差型 | 对比、纠错、认知升级 | `同样是【行为】，差别可能在【关键变量】` | 对比对象和结果要真实 |
| 从众型 | 有真实样本的趋势或推荐 | `【有来源的群体】常用的【方法】` | 没有证据时禁用人数、比例或“全网都在” |
| 身份型 | 明确垂直人群 | `【目标身份】遇到【场景】时，先做这一步` | 身份要与受众相关，不贴负面标签 |
| 时间型 | 计划、练习、快速操作 | `用【真实所需时间】完成【具体任务】` | 时间承诺必须可兑现 |

标题优先写得具体、可信、能预告正文价值。不是每个标题都要有数字、感叹号或“99%”。避免同时叠加多个钩子，导致读起来像广告拼贴。

### 标题优化

先检查原标题：主题是否可识别、受众是否明确、收益或问题是否具体、是否存在合理好奇、关键词是否自然、承诺是否被正文支持、是否过长或堆词。

默认给 3 个方向：

1. 信息更清楚：直接说主题和收获；
2. 痛点或场景更强：把问题放进具体时刻；
3. 好奇更强但仍可信：只保留一个合理信息差。

不要编造点击率。用户要求比较时，用“清晰度、相关性、可信度、好奇度、正文匹配度”五个维度说明取舍。

### 标题测试

真正的测试版本应能解释“测什么”，而不是随意生成四句：

- A/B 只变一个主要变量，例如“直接利益”对“痛点提问”；
- 其余信息、受众和事实承诺尽量保持一致；
- 为每个版本写测试假设和适用内容；
- 建议观察实际曝光点击、前三秒留存、完播或互动等用户已有指标；没有实验数据时不宣布胜者。

## 视频文案

### 口播分享

默认结构：

1. 开场约 3 秒：具体痛点、利益、反差、提问或数字钩子之一；
2. 正文：每 5–8 秒推进一个信息点；先结论，再解释，再举例；
3. 高潮或金句：总结真正的认知变化，不强行反转；
4. 结尾约 5 秒：回收承诺并给一个自然动作。

交付格式：

```markdown
【定位】受众｜目标｜预计时长
【开场 0–3 秒】
口播内容
【正文】
口播内容，按逻辑分段
【结尾】
总结或行动引导
【试读提示】预计字数与需要核实的事实（仅在必要时）
```

脚本应像人说话：句子短、主语清楚、每句有信息增量；删掉“众所周知”“在当今社会”等空开场。用户要求逐字稿时写完整台词，不用省略号代替核心内容。

### 剧情或反转脚本

采用“铺垫 → 冲突 → 选择或误判 → 有因果依据的反转 → 点题”。反转前埋至少一个可回看的线索，反转后人物行为仍然合乎逻辑。

交付可用表格：

| 时间或镜号 | 场景与人物 | 动作 | 台词或字幕 | 叙事作用 |
|---|---|---|---|---|

用户只要文案时，保留必要场景和动作即可，不扩写成完整拍摄方案。

### 知识科普

采用“常见问题 → 先给结论 → 2–4 个解释点 → 例子或演示 → 边界或误区 → 总结”。根据受众层级翻译术语：新手用日常比喻，专业受众保留必要术语但解释其意义。

所有数字、研究、健康效果、法律或金融结论都需要可核实来源。没有来源时，改写为一般性经验并标注待确认，或请求用户提供资料。

### 情感共鸣

采用“可见场景 → 一个细节 → 内心冲突 → 重新理解 → 留白或轻行动”。让情绪来自具体行为、时间、空间和关系，不用连续抽象形容词堆砌。避免替群体下绝对结论，也不要用羞辱、操控或灾难化表达逼互动。

## 互动话术

### 神评论或首评

可从四个方向生成：

- 共鸣：说出观众可能经历的具体瞬间；
- 提问：提出能继续讨论、且正文未完全回答的问题；
- 补充：增加一个相关技巧或边界；
- 轻反转：用无攻击性的幽默换一个视角。

不要伪装真实购买体验、虚构身份见证或组织刷评。用户要求评论营销时，输出品牌官方可透明发布的评论，而不是冒充普通消费者。

### 评论回复

普通问题使用“感谢或承接 → 直接回答 → 必要边界 → 下一步”。先回答用户真正问的内容，不要每条都导流。

如果缺少价格、库存、效果、售后规则等事实，用占位符并明确需确认；不把“因人而异”当成逃避所有问题的万能句。

### 引导关注

使用价值交换，而不是命令：说明持续能得到什么、内容与本条如何延续、下一期有什么具体价值。默认给一个主 CTA，不连续要求点赞、关注、评论、转发和私信。

### 差评应对

采用“承接感受 → 只确认已知事实 → 给具体解决动作 → 必要时转私聊处理个人信息”。可以感谢反馈，但不要机械承认尚未核实的责任。

对普通批评不要争吵、讽刺或威胁删除；涉及辱骂、泄露隐私、违法内容或垃圾信息时，可建议按平台规则隐藏、举报或留证，不坚持公开纠缠。

## 其他文案

### 账号简介

骨架为“身份或领域 + 持续提供的价值 + 可信特点或更新方式 + 一个引导”。一眼能看出账号服务谁、讲什么、为什么值得关注。资历、案例和结果必须真实；没有证明材料时不补写“多年经验”“服务上万人”等话术。

### 话题标签

从以下层级中选取少量相关标签：

1. 核心主题标签；
2. 垂直领域标签；
3. 具体场景或人群标签；
4. 已由用户确认的活动或热点标签。

标签必须与内容直接相关。没有实时热榜或搜索数据时，只称“相关标签建议”，不称“当前热门标签”。

### 合集标题

优先包含可检索的核心关键词，再补学习路径、目标人群、结果或集数，例如“Excel 入门到进阶｜30 个实用案例”。不要把关键词藏在情绪化句子里。

### 直播预告

按“明确时间和入口 → 适合谁 → 直播解决什么 → 已确认的议程或福利 → 预约提醒”组织。价格、库存、赠品、名额和截止时间必须由用户提供；否则使用占位符，不制造稀缺。

## 批量变体

批量版本至少在一个主要维度上不同：

- 受众切口；
- 使用场景；
- 开场机制；
- 核心利益；
- 论据或案例；
- 情绪强度；
- 内容结构；
- 行动引导。

先规划版本矩阵，再写文案。默认用表格标注“版本、核心角度、适用场景、成品”，便于筛选。发现多个版本只是词语替换时，重写其中重复的策略。
