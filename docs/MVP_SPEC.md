## 1. 先选一个足够具体的任务

**帮助卖床底收纳箱的小商家，把“买家不知道能不能放下”的疑问变成明确的购买说明，再根据实际采用情况和新咨询调整下一步。**

案例：演示收纳店 A（虚构），单款床底收纳箱，2只装 69.90 元。每只使用状态外尺寸 60×40×16cm，含盖、无脚轮、不可折叠。目标客户由商家描述为有床底收纳需求的租房人群，不当作实际流量画像。

模拟经营现状：最近7天发布了3条相关视频，单商品详情访客186人、支付订单0笔，另提供5条咨询摘录。访客来源尚未细分，摘录不是全量咨询，不能把这些数字拼成短视频转化漏斗。

模拟咨询包括：“床底17厘米能放吗？”和“入口只有15厘米，里面更高，能放吗？”等。首轮只使用第一批咨询；第二条在第二轮才出现，不能提前出现在首轮依据里。

### 为什么选它

- 一件实物、一个规格，尺寸和价格能人工核对；不依赖直播诊断、银行流水或监控。
- 能交付具体标题、购买须知和回复，不止给“优化内容”的建议。
- 两轮可以验证“已做过什么、没做什么、现在该不该继续改”，无需伪造订单增长。
- 比服装尺码、食品口味或餐饮核销更容易控制首轮演示变量。这是演示设计判断，不是已验证的需求规模。

## 2. 三页的共同规则

- 页名使用老板看得懂的话：**说清商品 → 选一件先改 → 拿去用，再复盘**。
- 一次仅处理一个商家、一个商品、一处优先验证问题。证据不足时可以没有诊断，先补关键事实。
- 顶部固定显示案例来源、分析来源、记忆状态。三者独立：模拟输入、预编写参考回答、本地保存均不能叫“MoneyAI已分析/已记忆”。
- 事实有来源、单位、确认状态和版本；修改事实后旧分析与成品标为过期，不能带着旧价格继续发布。
- “今天只剩5分钟”等临时限制，在复诊时重新确认；商品事实、长期经营限制与当日可用时间分开保存，不能把旧的当天状态当成永久偏好。
- 返回上一页不丢草稿。更换商家/商品时切换对应上下文，不能沿用上一商品的结果。
- 首版输入支持“加载演示案例”和手工编辑固定字段。JSON供开发加载；Excel、Word、OCR、链接抓取不列为已实现能力。可以添加来源备注，但没有解析器时不能显示“上传即识别成功”。
- 不画没有依据的健康分、增长率、成功概率和完整决策树。证据说明不是模型内部推理链。

## 3. 第1页：说清商品

**用户完成的事：确认系统到底知道什么、哪些地方不能猜。**

### 字段

默认先展示商品、适配事实、现有表达和经营限制。经营指标、来源细节、版本与历史折叠展开；不要把JSON里的每个元数据都变成老板必须填写的表单。

| 区域 | 字段 | 校验与展示 |
| --- | --- | --- |
| 商品 | 商品名、单次购买件数、售价/币种、目标客户、购买路径 | 核心字段逐项确认；件数为正整数、价格为正数；未知不填0 |
| 适配事实 | 单只外长/宽/高、单位、是否含盖/脚轮、是否可折叠、测量来源 | 本例的适配建议依赖这些字段；未知或来源冲突时不能给保证性答复 |
| 现有表达 | 当前标题、详情开头文字 | 只按用户提供的范围分析；不声称看过完整商品页或视频 |
| 经营限制 | 每次可用分钟数、能否改文字、是否允许降价/投流、其他不能做的事 | 明确的限制必须影响后续方案；能力未知时标明前置条件 |
| 现有线索（可选） | 咨询摘录、统计区间、访客数、支付订单数、流量/投放变化 | 没有指标也可做信息核对；缺失、0、统计口径分别保留 |
| 来源确认 | 每条事实的来源与用户确认 | 提供材料不等于已核实真实性；“用户确认”不是第三方验证 |

### 操作

1. “加载演示案例”填入固定样例，醒目标注模拟。演示预载的确认标记也要说明是模拟确认。
2. 用户修改字段，查看“需要确认”清单；冲突保留两条来源，不由AI挑一个。
3. 核对必要事实后点击“确认这些资料，看看先改什么”。只有来源链接时提示补内容，不伪造抓取。
4. 缺关键尺寸/件数时进入“待补资料”状态，保留草稿。只缺访客数据不阻止提供不依赖指标的改进建议。

页面底部提醒：**“这些资料能帮助我们提出一个值得尝试的改法，不能直接确定不出单的唯一原因。”**

## 4. 第2页：选一件先改

**用户完成的事：看懂依据，知道两个选项的区别，并主动选择。**

### 展示顺序

1. 一句话问题：**“目前提供的商品文字没有教买家如何判断床底是否适配；咨询里也出现了相同疑问，值得先把这件事说清楚。”**
2. 三类证据卡：已确认的商品事实、材料中观察到的情况、仍待验证的假设。每张卡都能定位来源。
3. 缺口：没有完整商品页和流量来源，不能排除价格、信任、流量质量等其他原因；不扩成全账号诊断。
4. 两条行动：

| 选项 | 实际动作 | 演示估计成本 | 风险/观察方式 |
| --- | --- | --- | --- |
| A：先改商品说明（推荐） | 把外尺寸和三处测量提醒放进标题/详情开头，附购买指引 | 约10分钟，0元额外支出；需能编辑文字 | 文字仍可能被跳过；看后续是否还问“怎么量/能否放下”，不承诺订单增长 |
| B：先用咨询验证 | 暂不改商品页，给当前有疑问的买家发测量问题和对应回复，记录真正卡点 | 约15分钟处理选定的几条咨询，0元额外支出；需能查看并回复咨询 | 只覆盖咨询者，增加人工回复工作；不能把少量回答代表所有访客 |

时间是为了测试资源约束的估计，不是实测耗时。可用时间低于估计时缩小动作或提示不可行，不悄悄忽略限制。

### 操作与异常

- “采用这条路线”只是进入成品页，不代表已经采用成品或实际发布。
- 同时保有“都不合适，告诉我们原因”入口；可以减少动作或先补材料，不能强迫选一个。
- 没有有效证据时显示补充问题，不为了排版硬凑一处诊断或两个可执行方案。
- 更改商品事实后，本页旧结果必须变为过期；需要重新核对后再生成。
- 调用失败明确失败和重试，不能无提示回退到预编写答案。

## 5. 第3页：拿去用，再复盘

**用户完成的事：拿到具体材料、记录实际执行，而后让下一次建议有依据。**

### A路线的第一轮成品（参考稿，不是真实AI运行）

标题：

> 床底收纳箱2只装 单只外尺寸60×40×16cm

详情开头：

> 一单2只，69.90元。每只使用状态外尺寸60×40×16cm，含盖、无脚轮、不可折叠。买前先核对三处：床底入口最窄/最低处、内部可用长宽与最低处、箱体抽出与开盖的操作空间。只知道床底高度，不能确认一定适配。刚好卡尺寸、有床脚或横梁挡住时，请先补充测量信息，不要直接下单。

购买指引：

> 确认空间和取用路径后，在当前商品页核对“2只装”、价格及结算页运费再下单。运费和发货时效尚未提供，本稿不承诺包邮、当天发货或所有床型通用。

不能自行写“统一留2cm就放得下”“可拆轮”“食品级”“无甲醛”“比同行便宜”。不要把外尺寸当作内尺寸、容积或承重依据。适配信息不足时不给“保证能放”的结论。

B路线交付的是测量提问、回复模板和记录清单，不强制生成无关标题；具体参考内容见JSON中的`alternative_artifacts`。

### 状态必须分开

| 状态 | 取值 | 作用 |
| --- | --- | --- |
| 选择的路线 | A / B / 暂不选 | 记录用户决策，不代表执行 |
| 成品采用 | 待决定 / 采用 / 部分采用 / 未采用 | 部分采用记录具体片段；拒绝收集原因 |
| 实际执行 | 未开始 / 进行中 / 已完成 | 已完成需要执行时间和实际改动；无需为证明执行索要隐私资料 |
| 反馈保存状态 | 未保存 / 保存中 / 已保存 / 失败 | 失败时保留草稿，不宣成功或进入依赖该历史的复盘 |
| 观察结果 | 未观察 / 有新咨询 / 有新经营数据 | “已选择”不能直接进入效果评价，缺数据不是0 |

按钮：复制单段、复制所选成品、记录采用与执行、保存反馈、带着已保存记录再看下一步。复制成功只表示复制，不显示“发布成功”。

### 两轮主路径

1. 首轮：商家选择A，复制并完成文字修改。保存价格、件数、尺寸等事实及发布版本。
2. 同保存新限制：今天只剩5分钟，不继续改标题、不新增投流或降价。选择A的原因：先完成一次文字修改，不做持续人工接待。
3. 第二轮模拟资料：商家说仍然0订单，新增咨询：“床底入口只有15cm，里面20cm，能放吗？”没有给出新的访客分母和可比观察窗口。
4. 合格回答：**上次说明已经完成，先保留；这条咨询当前不支持正常推入使用，不能拿内部20cm忽略入口15cm，也不能承诺拆盖后适配。给一段3分钟能发出的回复，沿用69.90元、2只装和尺寸事实；不要再次整页重写、改价或投流。**
5. 下一步可选：回复这一条具体疑问，或暂不进一步改动、只记录适配疑问。不因零订单直接判定A无效。

第二轮回复参考：

> 这款每只含盖外尺寸60×40×16cm，无脚轮、不可折叠。您提供的入口最低15cm小于箱体外高16cm，现有信息不支持正常推入使用，不能只看内部20cm就判断可放。请勿按可以挤压或拆盖后使用来下单；如可重新测量，仍需一起核对入口、内部长宽及抽出空间。

复盘仍使用第2、3页，在顶部标明“第2轮”。历史放在可展开区，无需第四页或独立运营后台。

### 真正的记忆验收

- 第二轮请求只发案例ID和新增观察，不重新发送首轮事实、成品和反馈；由实际存储读取历史。
- 保存失败、历史读不到时不能伪造复盘。显示“历史不可用”；允许明确改成仅根据当前材料的分析，但不能称为带历史复盘。
- 用相同的新增咨询，分别配“首轮已完成”和“首轮没执行”历史。前者不重复要求完成A，后者不能说A已经失败。
- 用已更新的限制再跑：如果老板明确恢复编辑能力/时间，可以更新限制，不能永久锁死旧偏好。
- 预编写JSON只能验证内容和交互。MoneyAI的跨会话读取、数据隔离和输出变化必须另外实测；如使用手动交接，界面与路演都如实说明。
- 首轮实际请求只传商家、商品、initial_snapshot及S1—S5来源，不能传整份包含未来反馈和参考答案的案例文件。可以用素材脚本导出独立请求。
- 增加未预编写答案的规格变体：另存外高14cm的新商品历史，再问15cm入口；不得仍输出“15小于16”。也不能仅因15大于14就保证适配，仍需核对长宽和取用路径。
