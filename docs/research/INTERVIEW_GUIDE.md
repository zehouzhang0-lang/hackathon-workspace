# 明日待核验：商家需求访谈提纲

准备日期：2026-08-27。**明天才知道具体商家；本文仅为备用提纲，没有已完成访谈、已招募样本或验证结论。** 今天与用户讨论候选需求，不预定行业或产品形态。

“输入、五维诊断、问题排序、行动方案、记忆、复诊”六模块仍是候选假设。明日访谈先不展示它们；MoneyAI、Codex CLI 接入与技术验收不应阻塞需求研究。

## 1. 先确认商家说的“一单”是什么

| 可能的成交路径 | 明日要核验的问题 |
| --- | --- |
| 抖音小店 | 没人购买，还是有人支付但退款？最终希望改善的是订单、收入还是利润？ |
| 本地团购 | 没人买券，还是买券后不到店核销？谁负责线上内容、门店接待？ |
| 私信等咨询线索 | 没咨询，还是有咨询但推进不到报价或成交？最终交易在哪发生？ |

同时问经营阶段：刚开始做；持续做却没有购买动作；有访问或咨询但成交少；曾经出单但最近不稳定。用实际经历区分，不设统一播放门槛，也不将不同路径、阶段合并成一类需求。

**待商家身份明确后再安排样本。** 可先访谈 1 名实际经营者，再计划补访 3–5 名同路径、相近阶段的经营者，其中尽量包括一名已有成交的人作对照；数量是计划，不代表已完成或已预约。若只接触得到一家，就只形成该案例的假设。优先找本人做关键动作的人，服务商观点不能替代商家经历。

招募可说：“我们想了解你做抖音时，哪些事情最难推进，不推销工具，也不保证出单。能否用 15–20 分钟回看最近一次经历？只看你愿意提供的脱敏资料，不需要账号登录。”

## 2. 15–20 分钟非诱导访谈

先说明匿名记录用途，允许跳过问题；录音另行征求同意。以下问题明日按实际情况选用，不必逐题问完。

| 时间 | 主问题 | 必要追问 |
| --- | --- | --- |
| 0–2 分钟 | 你负责哪些工作？你说“不出单”，具体指什么结果？ | 谁操作、谁决定花钱；产品、成交路径、经营阶段。 |
| 2–6 分钟 | 最近哪次投入没有达到预期，让你明显想处理？从那次讲起。 | 当时预期、实际发生什么、何时发现；能否看一条内容或一段脱敏记录？ |
| 6–10 分钟 | 从准备内容到客户付款或放弃，你实际做了哪些事？ | 谁做、用什么、在哪交接；最后完成了哪一步，下一步为何没继续？不要替他补出标准漏斗。 |
| 10–13 分钟 | 发现问题后你试过什么？后来怎样了？ | 实际花了多少时间和钱，买过什么服务或工具；是否执行完，怎么判断效果？ |
| 13–17 分钟 | 现在最难继续做下去的是哪件具体事？能带我们看一下原本怎么做吗？ | 哪些资料拿得到、寻找要多久；哪些拿不到；是不会做、没时间、没权限，还是别的原因？先让他描述。 |
| 17–20 分钟 | 如果今天继续处理这件事，你原本下一步打算做什么？ | 已安排的动作与资源；复述听到的卡点，请其纠正，再决定是否试做一个小任务。 |

追问具体事件和行为：“最近一次呢？”“当时做了什么？”“这个数怎么知道的？”不问“想不想要 AI 工具”“愿不愿意用”或假设性付费意向。收入损失若来自估计，要记录估算依据；没出的预期订单不是已证实损失。

## 3. 如有机会：访谈后的人工服务试验

另留 10–15 分钟，获同意后，针对刚才的真实卡点协助完成**一个**小任务。先看他用原方法做，再帮助；不轮流推销四种方案，也不要求他给概念打分。

| 待核验的需求 | 可试做的小任务 | 什么观察会改变方向 |
| --- | --- | --- |
| 不知道先改哪里 | 用已有材料写一个问题假设、证据、缺口及下一步动作 | 他若早已知道问题但做不出来，诊断可能不是主要交付。 |
| 知道方向但做不出内容 | 共同改一条现有内容的脚本或镜头清单 | 能否实际补全、进入拍摄准备？缺素材、供给或执行人时，继续生成选题未必有用。 |
| 产品表达、报价或承接难以推进 | 改一段真实商品说明或报价草稿，标清未知条件 | 能否确认并推进下一步？若无权改报价或产品，应找决策人或承认边界。 |
| 有线索却没有跟进 | 从脱敏记录整理一次待办和一条回复草稿 | 是否确有漏跟的有效线索？如果咨询本来就少，跟进管理可能不是首要问题。 |

记录他具体完成了什么、还差什么、是否需要返工。补交材料、完成剩余步骤、兑现具体复查约定，是比“挺好”更强的信号；预约未兑现不算复用，免费试做不算付费验证。当天只能观察任务推进，不能据此宣称成交提升。

**不替商家发布、投放、改线上价格或联系客户。** 不索要密码、客户身份或完整私聊。敏感原始资料不进共享仓库；仅保留获准的匿名摘要，截图和对外引用分别取得许可。

## 4. 匿名记录模板

未知项留空，不填 0；区分“核对过的材料、商家自述、研究者假设”。

```text
编号 / 日期 / 来源及样本偏差：
匿名记录与引用许可：
角色与决策权 / 行业 / 产品 / 路径 / 阶段：
“一单”的定义、统计时间与数据来源：
最近一次事件（预期、实际、匿名原话）：
真实工作顺序、工具、参与人：
最后完成的动作 / 停住的下一步 / 原因：
实际投入与现有支出（估计需注明）：
试过的解决办法 / 是否完成 / 效果依据：
能提供的材料 / 获取成本 / 缺口：
试做任务与选择理由 / 商家实际完成的动作：
没有解决的障碍 / 拒绝或中止原因：
下一步约定 / 后续是否兑现：
已核对观察 / 商家解释 / 研究者假设及反证：
尚不能回答的问题：
```

## 5. 明日如何使用证据

- **继续验证**：同路径、相近阶段的至少两个独立案例，重复出现相近任务卡点，材料可得，试做确实帮助完成原本停住的一步。这个人数只是筛选规则，不是统计证明。
- **改变方向**：判断已经清楚但执行停住，优先探索具体执行任务；有有效咨询却遗漏，才探索跟进；判断本身反复阻塞且材料充分，才探索诊断。
- **暂不做产品**：只有抽象抱怨、资料长期不可得，或障碍主要来自供给、履约、预算及决策权。先补证据、缩场景，不强行解释成 AI 问题。

明日结论可写：“在【匿名案例】里，【某类经营者】的【具体任务】反复卡在【一步】。协助【小任务】后观察到【真实行为】，下一轮要验证【未知项】。”

没有访谈就保留空白；**小样本不能验证市场规模，短时试做不能验证长期效果，已有支出也不能证明会为我们的产品付费。**
