# 测试设计：抖音成交操盘手 三页Demo V1.0

> 基准：`260828-抖音成交操盘手-Demo版PRD-V1.0.md`（产品真源）＋ 四张三页冻结稿设计图 ＋ 已拉取的 `douyin-conversion-agent-demo` V0.4 代码。
> 范围冻结口径：一个商品、一个优先断点、A/B 两个动作、执行一个方案、反馈后改判。
> 本文档是测试唯一真源：自动化用例进 vitest，页面流转按清单逐项人工勾选，不凭感觉判断“差不多能用”。

| 质量分档 | 商家授权导出 100 分高置信；合成案例 75 分中置信且标注“合成案例”；缺时间窗把中置信压到低置信（60 分）；七项缺失 12 分并逐项写出缺口 |

### 2.3 新增：`memoryRound2.test.ts`（15 例）—— 演示路径核心

**反馈保存后进入下一轮状态：**
1. 携带记忆时 `round` 升级为 2，Skill 链末尾挂载复盘记忆 Skill。
2. 改判理由可见且非空（PRD 10.6）。
3. “没有变化”反馈后不再重复首屏改法，A 方案切换为购买问答区，成品标注“不重复上一轮首屏改法”。
4. 第二轮问答成品只含已确认事实（USB-C充电）与真实顾客问题，未知项继续标注待验证。
5. 实验编号按轮次递增且逐段对齐：`EXP-JUICER01-click_cart-{A|B}-R{1|2}`（与 PRD 9.4/10.4 完全一致）。
6. 第二轮 B 方案单一变量切换为“真实问题验证视频”。

**保持不变的条件（单变量实验合同）：**

7. A/B 两方案各 8 项合同字段（假设、控制组、主指标、护栏、最低样本、观察周期、停止、回滚）在两轮**逐字段相等**。
8. 控制组明确锁定“价格”“流量来源”不改。
9. 改判只换单一变量（详情页首屏→购买问答区），主观察指标“商品点击→加购率”不变。
10. B 方案内容在改判前后逐字段原样，只升级 A。

**不同反馈触发不同改判：**

11. 只“标题不能改”→ 保留标题重写成品（headline 退回原文案），但**不**切换验证变量。
12. “没有测试数据”→ 成品含“待验证性能不作承诺”，改判说明含“不输出打冰”。
13. “不能降价”→ 改判说明含“保持价格不变”。
14. “没变化”与“标题不能改”同时出现 → “没变化”优先。
15. 无匹配关键词的反馈仍进入第二轮并引用老板原文。

## 4. L3 三页流转验收清单（人工，P0 为主）

> 使用“载入榨汁杯演示案例”作为唯一预置数据。每条执行后勾选；任何 P0 失败即阻断路演。

### 4.1 第一页 → 第二页（触发：老板确认）

- [ ] **P0** 点击“载入榨汁杯演示案例”后，AI 整理区出现六类信息：已读取数据、商品与经营背景、老板的判断、尚未确认、经营限制、数据缺口。
- [ ] **P0** 已读取数据五段数字与演示案例一致：播放 58,000｜商品点击 1,450｜加购 96｜下单 54｜支付 42。
- [ ] **P0** 点击“确认，开始分析”后进入第二页；未确认前停留在第一页。
- [ ] P1 点击“有信息不对”可修改字段；修改后确认，第二页读到的是修改后的值（userCorrections 生效）。
- [ ] P1 点击“补充资料”停留在第一页且不丢失已上传内容。
- [ ] P1 数据缺口处显示“缺少投流和退款数据”，而不是显示 0。

### 4.2 第二页 → 第三页（触发：老板选择 A 或 B）

- [ ] **P0** 漏斗图五段数字与第一页一致，“本轮优先验证：点击到加购”徽标挂在商品点击→加购之间。
- [ ] **P0** “这还不是已经确认的根因”提示可见；“AI为什么这样判断”区分已确认事实 / 待验证假设 / 还不知道 / 本轮调用。
- [ ] **P0** 只出现方案 A、方案 B 两张卡，均含具体做什么、成本、风险、本轮保持不变。
- [ ] **P0** 点击“选择方案A”进入第三页后，页面**只显示方案 A** 的成品与实验卡，不出现 B 的任何成品痕迹。
- [ ] **P0** 点击“选择方案B”进入第三页后，同理只显示 B。
- [ ] P1 “这个判断符合你的实际感受吗”三个按钮：符合→展开 A/B；“不符合，重新判断”→回到判断而非死路；“不确定”→解释差异、不替老板拍板。
- [ ] P1 “两个都做不了，告诉AI原因”有明确接收路径，不产生报错或空白页。

### 4.3 第三页：执行与反馈 → 下一轮状态（触发：保存本轮记录）

- [ ] **P0** 实验卡八项齐全：本轮只改什么、本轮保持不变、主要观察、最小样本、观察时间、护栏指标、停止条件、回滚方式。
- [ ] **P0** 成品区有“仅使用已确认商品事实”标识；成品中不出现打冰、续航等未确认性能承诺。
- [ ] **P0** 反馈三选一：我已经执行 / 只执行了一部分 / 我没有执行；“稍后回来补充”可离开且不强制保存。
- [ ] **P0** 选择状态并填写说明后，点击“保存本轮记录”→ 第三页**就地进入下一轮状态**（不需要回第一页重来）。
- [ ] **P0** 下一轮状态四要素齐全：
  - [ ] “第一次实验已经记住”横幅；
  - [ ] “上一轮发生了什么”四格：上一轮动作→执行情况→观察结果→当前结论，结论为“证据不足，不能认定方案A有效”一类表述；
  - [ ] “本轮不再重复（原动作）→ 下一步建议（新方案）”并写明理由；
  - [ ] “这个商家的实验记忆”时间线含第一轮（已执行/暂无足够证据）与第二轮（待执行）。
- [ ] **P0（保持不变条件）** 第二轮实验规则中“继续保持不变”仍锁定价格、商品页、投流来源；主要观察指标与第一轮同段位；停止条件、回滚方式仍在。
- [ ] **P0** 第二轮建议不是第一轮的重复：若第一轮执行了 A 且无变化，第二轮不再推荐继续修改同一处。
- [ ] P1 保存后**刷新页面**，最近反馈与下一轮状态仍在（localStorage `douyin-conversion-agent-memory-v1`）。
- [ ] P1 “重新开始演示”清空记忆后回到第一轮；不出现服务端旧记录“复活”已清空的组合。
- [ ] P1 只填“感觉没效果”时，系统追问最低必要信息（新增样本量、指标是否变化），不直接判定实验失败。

### 4.4 演示路径彩排（每次部署后）

按 PRD §20 六分钟路径完整走一遍：载入案例 → 确认 → 看断点 → 选 A → 执行稿+实验卡 → 记录“已执行+无变化+标题不能改”→ 展示改判与记忆时间线 → 展开专业详情展示 MoneyAI 证据。全程录屏作为路演备用视频。

## 5. L2 数据契约测试规格（第一页 intake 实现时落地为 vitest）

对应 PRD §11 契约，实现后新增 `src/engine/intake.test.ts`：

1. 老板未提供的漏斗字段保持 `null`，任何环节不得把 `null` 转成 `0`（含展示层：显示“未知”而非 0）。
2. “我觉得／可能／应该”开头的输入归入 `owner_hypothesis`，不得进入 `confirmedProductFacts`。
3. `evidenceLedger` 每条含 field、value、status、source；截图识别失败时对应字段 status 为 `unknown` 且允许手动补充。
4. 用户修改写入 `userCorrections`（before/after），后续分析读修改后的值。
5. 时间窗不一致的两份来源同时存在时，第一页停止分析并要求确认，不得带病进入第二页。
6. 公开商品页资料只能进商品事实，不得写进后台漏斗证据（source 标记分离）。
7. 合成案例载入后 `sources` 含 `synthetic`，页面任何位置不得把该组数据表述为真实商家数据。

## 6. L5 降级与错误状态清单（PRD §15 逐行）

- [ ] 截图无法识别 → 提示未识别出可用信息，允许手动补充，不编造字段。
- [ ] 表格格式不支持 → 引导转 CSV 或粘贴。
- [ ] 漏斗顺序异常 → 拦截并提示完整顺序要求（已由 L1 覆盖引擎侧）。
- [ ] 时间窗不一致 → 停止断点判断，要求确认。
- [ ] 关键数值缺失 → 显示未知，只追问一个会改变判断的问题（最多三次）。
- [ ] MoneyAI 不可用 → 页面展示本地可信结果，明确标注“本地”，不假装实时调用成功。
- [ ] 模型返回非法 JSON → 不展示半成品，回退本地规则（BFF 结构硬化已拦截缺字段）。
- [ ] 本地记忆读取失败 → 禁止宣称“已根据历史改判”。
- [ ] BFF mock 模式 → 页面明确标注“Mock演示模式”。

## 7. MoneyAI 证据链验收（PRD §13.4）

- [ ] 专业详情可见：MoneyAI 已调用／不可用状态、请求 ID、模型名、Skill 链、分析来源（moneyai / local_fallback）。
- [ ] 断点标题、证据、质量分、Skill 链、实验合同在 MoneyAI 返回后仍为本地锁定值（模型只改假设、A/B 文案、成品）。
- [ ] 反馈保存后 BFF 收到 record；断网保存失败时演示不中断（静默降级 + 本地仍可读）。

## 8. 缺陷观察项（本次设计期间发现，交开发主手确认）

1. ~~Boss 模式反馈原因失真~~ **已修复**：`saveBossOutcome` 改为记录老板当轮真实选择（已执行／部分／未采用），不再把经营限制误存为反馈；同时 `declined` 状态也会阻断下一轮重复推荐（PRD 10.5「排除不可执行动作」）。回归用例见 `memoryRound2.test.ts` 最后一组。
2. **0 与未知混用**：`analyze.ts` 的 `rate()` 把分母 ≤0 直接算 0%，与“缺失值不得转成 0”原则冲突；第一页 intake 落地后应在进入分析前拦截关键漏斗为 `null` 的情况（见 §5.1）。
3. **一条记忆槽位**：记忆按“商家+商品”只存最近一条（旧记录被覆盖），多次实验列表属 P1，当前口径下可接受，但演示时勿点击两次保存后期待两条时间线。
