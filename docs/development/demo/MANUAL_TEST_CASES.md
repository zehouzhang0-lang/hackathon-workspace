## 3. 判定与证据规则

- **通过**：本例所有必测检查点均实际观察到；填写实际结果和证据，不能只写“看起来正常”。
- **失败**：已执行，但某一检查点不符合预期；记录步骤号、页面原话和截图。
- **阻塞**：服务、前置数据、浏览器能力或上游失败使本例无法执行；写清原因，不记作通过。
- **未执行**：尚未操作。可选子项没跑要单独注明；不要把整个范围都标通过。

MoneyAI“未接通”提示正确，可以使“如实披露”检查点通过，**不能使 MoneyAI 业务接通验收通过**。下载提示只证明请求发出，必须在下载列表找到并打开文件才算下载检查通过；复制必须粘贴核对。

出现泄露其他会话内容、无确认清空、未录音却编造转写、复制／查看被记为已执行等问题时，停止该链，保留合成证据并反馈。不要继续输入真实资料。

### MT-00｜空会话、中文首屏与能力提示

优先级：P0。前置：独立空测试配置；未载入示例。对应 D15、D17、D18、D25。

**操作**

1. 打开第一页，等页面完成加载；截一张首屏，记录浏览器、缩放与实际尺寸。
2. 查看“路芽”、三步导航，以及“用一分钟，把你的商品讲给我听”。

4. 展开“手动补充”，保持空白，再输入几个空格；观察“整理并核对”，随后删掉空格。

**预期**

- 中文没有乱码、方块字、文字重叠或主操作被遮挡；导航能辨认三页职责。
- 没有预置商家、路径、执行或反馈，也不自动申请麦克风权限。

优先级：P0；独立回归，不阻塞 A 组试跑。前置：独立空测试会话。对应 D05、D07、D08、D21。

**操作**

1. 页头选“合成案例 · 床底收纳箱”，点“载入示例”并确认替换。
2. 不改原文、不改卡片，点“整理并核对”→“理解正确，继续”；出现补问时全部留空点“先跳过”，最后点“开始分析”。
3. 记录第二页来源标签、路径数量及标题、结果类型。
4. **仅在确实出现两条专属路径时**，分别查看“把尺寸和套装说明写清楚”“先统一尺寸咨询回复”，核对情景：假设 100 名可比访客 × 0%／1%／2% = 0／1／2 笔。
5. 若步骤 4 可执行：明确选择第一条进第三页，再返回第二页仅查看第二条，不点“就做这件事”；通过顶部第三页入口核对原选择仍是第一条。

**验收目标与已知实际风险**

- 完整、未经用户改写的合成主案例应能演示两条专属路径；同一组情景条件不是成功概率、结果必然上下界或路径增量排名。
- 仅查看另一条路径不应改变已经明确保存的选择；“正在查看”和“已选”须可区分。
- **历史基线缺陷**：首次首页确认新增intake曾被当作输入变化并清fixtureId，导致专属两路退化。当前C3已复现并修复，原样确认的纯逻辑回归通过，真实UI仍未验证。运行当前代码时不再把此缺陷当作预期；按开头MT30验证，新榨汁杯的C4专用路径未交付则是另一项明确缺口。
- 如果实际出现退化，本例记“失败”，步骤 4—5 记“阻塞”；不要把单路当两路验收通过，也不要通过控制台改标记或手动塞预编答案来绕过。
- P2 原任务另有查看／已选状态与重复选路待修。若两路恢复后仍发现串选，单独记录，不改本例的正确预期。

证据：载入后原资料、第二页路径与模式；实际能进入步骤 4 时再保存相应证据。

### MT-17｜口径冲突不能拼成漏斗

优先级：P0。前置：新的独立空测试会话，或已保存证据后在测试配置清空。对应 D06、D08。

**操作**

1. 页头选“合成案例 · 口径冲突”，点“载入示例”并确认。
2. 保留原文，整理、核对、逐问留空跳过，确认进入第二页。
3. 在第一页来源或第二页依据中核对两组数据：访客 186，2026-08-18 至 2026-08-24、短视频；支付 0，2026-08-01 至 2026-08-17、直播。
4. 查看结果、限制和报告可见摘要。

**预期**

- 日期与渠道差异被保留，不能把这两条算成同一漏斗的成交率。
- 结果应说明口径不可比／暂不可估，提供核对步骤；不能据此确定问题在转化环节。
- 0 支付仍为记录原值，未知项不补 0；报告不能把差异删掉再输出确定结论。
- 不把此例“安全退回有限参考”与 MT-16 的完整案例退化混为同一判定。

证据：两条来源口径、不可比提示、结果说明。
