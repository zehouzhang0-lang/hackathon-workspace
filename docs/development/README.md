# 开发者与开发 Agent 入口

这里负责把对话、队友资料和产品决定整理成可以交接的开发任务。**它是仓库文档区，不是已上线的网页、自动知识库或 Agent 调度系统。**

更新：2026-08-28。当前可准备和下发文档类任务；没有开始应用实现。

## 三分钟了解项目

议题是“抖音做了不出单怎么办”。产品帮助商家整理现有资料，理解可能的成交断点，并比较下一步经营路径、可能结果和承担的风险。张泽厚负责前端启动，其他实际开发分工待团队补充。

第一页的交互主流程已确认。今天又确认第二页应承担初步分析、可视化路径、证据链、风险、结果区间和决策报告下载；数据不足允许明确标注假设的情景测算，不强行给成功概率。第三页仍是讨论稿。视觉、具体技术栈、模型、存储与接口尚未确定。

## 可以直接复制给开发 Agent

```text
请先阅读根目录 AGENTS.md、docs/development/README.md 和
docs/development/CURRENT_BRIEF.md，再执行 docs/development/NEXT_TASK.md。
先核对新资料与已确认需求是否冲突，只在该任务明确允许的范围内工作。
目前这份任务只产出文档草案，不写页面、不安装依赖、不接真实商家接口。
完成后汇报产物、验证结果和待确认项，不自动进入下一任务。
```

这段话用于显式下发当前 DEV-001；本次建立入口时没有执行它。其他任务须用具体任务文件替换路径，不能把模板占位内容当成命令。

## 队友投喂资料后如何形成开发指令

1. 接收原始内容，先判断敏感性和共享许可，不要求队友先填完整表。
2. 在收件区登记来源和处理状态，提炼事实、需求、假设与待验证建议。
3. 对照当前需求基线列出新增点和冲突。没有确认的内容保持待定，不静默覆盖产品决定。
4. 经确认后更新基线及受影响页面，用任务模板生成一个有范围、依赖、输出和验收的新任务。
5. 显式下发任务；完成后记录真实验证结果，再讨论或下发后续工作。

事实可信度、需求批准状态、任务执行状态分别记录。收到一张截图、队友说“建议这样做”、Agent 生成了方案，都不等于需求已经获批或功能已实现。

## 本机资料与仓库同步

- 根目录 `.local-inbox/`：未脱敏原件的本机暂存位置，已被忽略，不随 GitHub 同步；其他设备需要通过获准方式另行取得。
- 本目录的 `inbox/`：只保存获准共享且已脱敏的摘要与登记，不放账号密钥、原始个人流水或私人团队聊天。
- 设计资源插件与 MCP 的安装状态因设备而异；GitHub 同步不会自动同步插件、账号或凭据。

Codex 的项目说明采用根目录 `AGENTS.md`；新会话的读取机制见 [OpenAI 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。其他开发 Agent 可以显式阅读同一文件；不要假定所有运行时都会自动加载。
