# 抖音成交实验 Agent Demo PRD

## 产品目标

为线上抖音实物电商商家提供一个可演示的成交复盘闭环：输入商品与漏斗数据，识别一处最值得验证的成交断点，输出可直接执行的改法，并记住商家反馈以改变第二轮建议。

## 使用对象

- 首要用户：已经在抖音发布内容并挂商品，但有点击、少加购或少成交的线上实物电商商家。
- 演示对象：黑客松评委、投资人和现场观众。

## 核心功能

### 功能零：老板决策流

- 默认进入老板模式，每次只呈现一个需要回答的问题。
- 只保留“是／否／不确定／换一个”等老板语言，不要求理解Skill或实验术语。
- 以只读流程图展示当前位置、已走路径和可能分支，老板不能拖节点或改连线。
- 专业数据、Skill链路与MoneyAI证据进入“专业详情”或折叠区。

验收标准：

- 打开页面后第一个可执行问题是“这组数据能代表同一件商品吗”。
- 1280宽屏中流程与当前问题同时可见；900窄屏中当前问题出现在流程图之前。
- 缺数据、不确定和做不到均有明确下一步，不进入死路。

### 功能一：输入与事实确认

- 输入商家、商品、价格、目标用户、经营限制。
- 输入数据来源、统一时间窗、内容ID、商品ID与播放、商品点击、加购、创建订单、支付五段漏斗数据。
- 输入商品页现状和顾客高频问题。
- 明确区分合成案例、商家授权脱敏导出与公开真实电商数据。

验收标准：

- 默认案例可以一键恢复。
- 必填信息为空或漏斗数据不合理时给出明确提示。
- 页面不出现门店、到店、预约或核销场景。

### 功能二：成交断点分析

- 计算播放到点击、点击到加购、加购到创建订单、创建订单到支付转化率。
- 先输出数据质量分，再锁定断点并自动路由一个领域专家Skill。
- 区分已确认事实和待验证假设。
- 每轮只识别一个最高优先级断点。
- 给出两种可选改法，并标注代价与风险。

验收标准：

- 固定案例会优先识别“点击后的商品信息与信任承接”。
- 不把相关性表达成已证明的成交原因。
- 不生成没有输入证据支持的商品性能承诺。

### 功能三：输出、反馈与第二轮记忆

- 输出可直接替换的商品页首屏信息。
- 输出含主指标、护栏、最低样本、观察周期、停止和回滚的下一步成交实验。
- 记录尚未执行、采用、部分采用或未采用，以及原因和执行结果。
- 本地保存反馈，并据此改变第二轮建议。

验收标准：

- 刷新页面后仍能看到最近一次反馈。
- 输入“标题不能改”后，第二轮不得继续要求修改标题。
- 输入“没有测试数据”后，第二轮不得编造性能参数。

## 页面清单

仅一页，提供两个模式：

1. 老板使用，默认入口：只读成交路径＋当前问题卡；宽屏左右并排，窄屏问题优先。
2. 专业详情：保留输入、分析、输出三栏，用于修改经营事实和核验系统依据。

老板模式底部另有可折叠的“查看系统怎么判断”，用于展示数据质量、漏斗、Skill和MoneyAI证据。

## 本轮明确不做

- 抖音登录、Cookie、爬虫和私有后台抓取。
- 多商家、多商品和账号系统。
- 数据库、支付、自动发布和正式线上部署。
- 未经验证的订单增长、ROI或真实归因承诺。
- 将MoneyAI内部未公开接口冒充正式开放API。

## MoneyAI边界

MoneyAI作为总控执行已路由的领域专家Skill，生成假设、A/B改法与成交成品。本地质检、断点、事实和实验合同保持锁定；真实推理失败不得影响本地可信结果。
