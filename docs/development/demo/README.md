## 本轮建议的实现取舍

- 三份独立HTML，共用CSS和原生ES modules；不初始化三个React工程。功能在本地浏览器真实可交互，生成内容注明演示来源。
- 用现有Python提供同一来源的本地HTTP服务；不依赖`file://`双击运行，不依赖CDN、云数据库或MoneyAI才能看Demo。
- 先真实实现文件接收/预览、受支持文本解析、页面跳转、状态保存读回、文案复制及HTML报告下载。
- 任意图片OCR、抖音后台抓取、真实模型诊断、统计预测和MoneyAI长期记忆不在本轮默认实现范围。图片未识别就写未识别，演示模板不能冒充实时模型输出。
- 第三页采用“只交付所选行动所需内容＋可选轻量反馈＋明确保存＋带反馈回第二页”的最小提案。
- 视觉先统一：不直接沿用被否决旧稿，也不因为V0.4已有CSS就采用其深色风格。

## 开始开发的顺序

1. 用户审阅三页分工与本轮取舍；统筹更新范围状态。
2. 统筹依照[视觉简报](DESIGN_BRIEF.md)，使用Product Design与Build Web Apps确认一个共同视觉目标；三页按同一母版展开，不能各自选三套风格。
3. 统筹按[共享契约](SHARED_CONTRACT.md)一次性交付`demo/shared/`、合成示例、公共壳和冒烟测试。暂不写三个页面；记录SHARED_READY的实际验证证据。
4. 用户在同一本地工作目录打开三个开发对话，分别下发下面的prompt。三个对话只改各自文件，共享文件只读。
5. 每页分别验收与交接；统筹执行[跨页检查](QA_MATRIX.md)，统一提交和同步。未验证的能力如实列出。

## 本机环境与同步

已实际检查：Windows PowerShell；Python 3.13.9、Node 24.14.0、Git可用。21st检索通过；React Bits已修正本机进程cwd并在新连接验证注册表/检索，旧会话连接仍需重载。详见[MCP记录](MCP_SETUP.md)。本轮未安装组件，Product Design没有已保存的视觉母版。

共享底座建立后，从仓库根目录运行以下命令即可提供静态页面；**当前尚未创建demo目录，也未启动服务**：

```powershell
python -m http.server 4188 --bind 127.0.0.1 --directory demo
```

只服务`demo/`，不暴露仓库根目录及`.local-inbox/`。三页使用同一个`127.0.0.1:4188`来源，否则本地存储会隔离；端口被占时由统筹统一调整，不让各Agent单独换端口。切勿结束未知进程来抢端口。

同目录并行期间，页面Agent不执行pull、checkout、reset、commit、push，不改根README/AGENTS/进度/依赖锁文件。统筹在合并检查后同步一次；不得`git add .`误带队友进行中的文件。GitHub同步代码和文档，不同步浏览器商家数据、登录或MCP凭据。
