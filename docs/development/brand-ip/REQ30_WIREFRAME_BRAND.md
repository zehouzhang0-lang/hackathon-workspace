公共三步统一为**资料确认 → 找到优先问题 → 执行并记录**；“反馈后改判”是P3同页状态，有明确入口和返回，不新增第四页。“商家中心／演示商家”只指当前受控项目会话与记录，不暗示个人账号或多商家隔离已实现。

## 3. 状态色不能制造成功

不新增最终色板；旧版深青绿、暖白、琥珀仍为候选。主按钮、当前页、正在查看、已选方案、事实来源与执行结果不是同一语义；不用颜色或勾号代替状态文字。

| 状态 | 必须保留的区别 |
| --- | --- |
| 未知与执行 | 三个执行按钮初始均不选；“我没有执行”须用户明确报告，不能由未反馈、稍后补充或暂不继续推断。已执行是执行自述，不代表动作有效或平台已核验 |
| 材料与事实 | 已接收、已解析、待核对、商家确认与外部核验分别标明。缩略图、文件图标或绿色边框不等于OCR／Excel解析成功；“符合”不证实根因 |
| 保存与记忆 | 草稿、保存中、本机已保存、本机已读回、MoneyAI写入、MoneyAI读回分别取真实状态。健康可达不等于业务接通，失败保留错误及重试，不变成绿色完成 |
| 候选与下一轮 | 未明确开始前写“候选方案，尚未开始”，不生成正式“第二轮待执行”记录；明确建轮与实际执行继续分开，暂不继续不抹掉已发生行动 |
| 风险与假设 | 重要未知、限制、证据不足和风险在相应决策前可见；缺退款数据不等于没有退款。警示与错误保留独立语义，不随品牌主色一并换绿 |

## 4. 草稿中需按证据修正的表达

只修正下列断言，不撤掉其所在模块或操作：

- 图4“顾客在哪一步流失最多？”不能让加购高亮冒充最大流失。按锁定第7节使用“顾客在哪一步流失？”与“本轮优先验证”区分，计算、口径冲突和来源仍可查看。
- 图4“本轮调用／专家Skill”只列实际调用或处理来源；未调用时如实标计划模块、本机规则或演示，不编造专家工作流水，也不展示模型私有思考。
- 图3的已执行高亮是草稿状态，不是新会话默认值。未知商品性能、售后和清洗规则标待补；100次、24—72小时须有计划来源或明确合成假设，不承诺统计充分或效果。
- 图2“第一次实验已经记住”改为对应实际存储位置的回执；本机和MoneyAI写入／读回分开，不承诺“下次一定读回”。“已经验证过A”按实际记录写已尝试／已执行及证据限制，不把无变化当作失败或证伪。
- 图2建议变化和A→B只展示共享再判断的真实结果及反馈来源；保留继续观察、补数据、暂停或换实验的条件。下一轮未开始时，预览、规则与时间线均标候选。
