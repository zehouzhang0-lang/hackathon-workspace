# 三页共用视觉简报

状态：**设计要求与选型流程，尚无已批准视觉母版。** 不把下列文字视为最终色板或允许直接开写UI的设计稿。

## 产品体验

给不熟悉运营指标的商家一个能看懂、能做决定的经营助手。三页像同一个产品的连续三个步骤，分别解决“交什么”“选什么”“怎么做”，而不是三张长报告或三个功能密集后台。

| 页面 | 首屏焦点 | 次级信息 |
| --- | --- | --- |
| 1 说清问题 | 一句问题描述＋一个明确的材料投递区 | 收到的资料、可纠错整理、一个关键缺口 |
| 2 看清选择 | 路径之间的实际取舍与当前查看路径的结果/风险 | 可展开的来源、条件决策树、完整报告 |
| 3 拿去执行 | 所选动作的成品或步骤、一个主要取用按钮 | 使用边界、实验计划、可选反馈 |

不要大幅营销标题、装饰数据、雷达健康分、满屏卡片、三页都出现完整资料和分析、为了显得AI而放聊天框。没有确认的新卖点、收益数字或徽章不进入首屏。

## 必须一致的视觉要素

- 同一产品名称、页头、三步导航、容器、字体层级、按钮、表单、状态提示、来源/风险标识；同一套设计token，不在页面CSS重新定义主题。
- 主要内容和动作要适合普通笔记本演示，正文优先16px以上、辅助信息不低于12px；按钮至少44px触达区，清晰可见的焦点样式。
- 1440×900主稿，另检验1280×720与390px窄屏；不横向溢出，不依赖仅hover才出现的关键说明。
- 色彩、留白、字号、边框与圆角由所选母版确定。浅色/深色未选，旧视觉与V0.4深色CSS都不自动成为目标。
- 动效用于投递反馈、展开、选路和状态变化，优先150–250ms，支持减少动态效果；不用无关粒子/光球掩盖信息。加载动画必须对应实际异步任务，不能模拟已经完成解析。
- 保持真实文字、按钮与表格可交互；设计截图不能整张当网页使用。图表是业务数据表达，不是装饰素材。

## 统一视觉的产生方式

1. 统筹使用用户指定的Product Design与Build Web Apps。按已安装skill读取上下文与约束；未发现已保存母版，当前没有图稿可直接实现。
2. 视觉讨论时，针对同一产品简报生成并展示三种视觉候选，让用户选一个。遵守用户逐页确认要求；不要让三个页面Agent各自再开一轮主题投票。
3. 选中母版后补齐同风格的三页可读参考与必要状态；用户确认相应页面后再实现。页面不同任务可以不同布局，但不改变全局风格。
4. 统筹提取token、排版、公共壳、基础控件、图标规范与交互状态，保存到共享目录。参考图保存到仓库内非敏感`demo/assets/design/`，入口登记相对路径。
5. 三个页面Agent忠实落实各自参考与契约；新的重大布局/风格改动回统筹确认，不能用“更好看”为由分叉主题。

用户明确要求三个对话接通21st与React Bits：先按[MCP约定](MCP_SETUP.md)实际验证检索，再作为组件/动效来源；不为使用它们而各改一套框架、安装无关依赖或替换用户已选设计。图片资产需要时使用ImageGen；本轮已做只读资源检索，不生成图片、不安装组件。

## 页面验收共同标准

使用Browser插件的应用内浏览器优先检查；每页记录实际点击链、窄屏、键盘、控制台和来源/风险可见性。将同尺寸实测截图与批准参考一起查看，至少核对布局、字号、颜色、控件/间距、内容密度五项。

每页写自己的QA记录：已检查、失败、未检查要区分。截图漂亮不等于业务流程通过，静态构建通过也不等于视觉一致。若环境缺少插件或浏览器，明确具体缺项，不捏造调用或验收记录。
