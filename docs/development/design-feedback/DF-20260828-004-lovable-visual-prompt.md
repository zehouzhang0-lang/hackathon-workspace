# DF-20260828-004｜Lovable 视觉基底试验提示词

来源：张泽厚于2026-08-28明确要求，基于现有功能模块生成给Lovable的提示词，尝试新的视觉基底。用户授权的是本次提示词准备；未在本任务创建Lovable项目、上传资料、调用模型、付费或改动现有页面。

适用：三页独立PC网页，1920×1080先行。以下可复制区已区分固定产品职责与本轮视觉建议；它不是最终设计批准、现有工程换栈指令或业务接通声明。本轮没有新增设计图或运行截图。

## 可直接复制到Lovable

```text
请为中文产品「路芽」制作一套可交互的 PC 网页视觉原型。这是一次视觉基底试验：保留下面的功能，重新设计布局、排版和组件，不继承旧页面样式。请交付实际可点击的界面，不只给设计建议或营销首页。

## 1. 产品与体验
用户是不熟悉运营术语的小商家，希望解决「抖音做了，但不知道为什么不出单、下一步做什么」。产品依次帮助他：说清情况 → 看清并选择下一步 → 拿到内容去使用。
品牌名已定为「路芽」，理念是「把下一步看清楚，把每一次选择接起来」。理念不必每页重复。
追求普通人打开就会用的亲切感，参考我所描述的豆包式低上手成本与渐进信息组织；没有提供豆包截图，不要求复刻其布局、品牌或图标，也不要因此做成无限聊天。
必须保持三个独立页面、同一套视觉系统。每页突出当前任务；完整依据和其他选项仍有容易找到、可以返回的入口。

## 2. 视觉方向
以 1920×1080 桌面网页为主，本轮不做手机稿。气质温暖、清楚、克制，有完成度和可操作感。
本次可试用暖白 #FAF9F6、白色功能面、深青绿 #245E58 主操作、深色正文 #243330，少量琥珀点缀。这是实验色板，可为可读性细调，不是已批准的最终品牌规范。错误、警告、选中和成功有独立语义，不能全部刷绿。
重视真实中文：系统中文字体，正文约 16–18px，辅助文字清晰，任务标题约 28–36px，控件至少 44px 操作区域。留白用于分组，不把宽屏做成一条窄长文，也不用巨型标题占掉首屏。
公共页头只保留「路芽」、简明三步进度及必要状态。功能感来自清楚的输入区、比较项、预览区、工具栏和按钮；按任务分区，不给每段文字套卡片。
每页一个固定标题可用一次轻微折叠展开动效，总时长不超过 800ms；副标题静态，支持减少动态效果。其他交互过渡短而安静，不动画风险、数字或保存状态，不做循环漂浮、打字机或虚假分析进度；动效不阻塞操作，失败时静态显示。
本次没有提供获准上传的 IP 图片，先用文字品牌，不生成替代吉祥物或假装已有品牌资产。

## 3. 三个页面

### 第一页：说清情况
首屏突出语音入口，材料次要，「改用文字输入」默认折叠但容易找到。可以一句话或一份材料开始，不要求先填表。
保留等待开始、听取、转写、整理、核对、逐问、确认这些阶段，以及停止、不可用／失败和改用文字的状态。此次不接真实录音或识别：使用「体验语音流程」并就近标注「演示，不录音」，不要申请麦克风权限或假装正在听用户说话。
材料入口仅覆盖 TXT／CSV／JSON，展示已选材料、移除及格式不支持状态；文件只在浏览器本地处理。本次不增加图片理解、PDF、链接导入或后台上传。
内容进入核对后，按需呈现商品、价格规格、平台、人群判断、场景判断、问题、已做动作、限制、数据与缺口九组摘要；可修改、可保留未知，不能变成九项必填问卷。原始讲述和修改内容可回看，判断不能冒充商家事实。
最多主动补问三次，一次一问，可以跳过；不要强制问满三次，跨页不重置额度。
确认后的主操作：「确认，看看有哪些办法」。

### 第二页：选择下一步
首屏先给一句简短判断和可比较的路径，避免长篇开场。比较项用一致结构展示：先做什么、适用条件、投入、关键风险、重要未知、简短来源摘要和可能结果。示例可有两条路径，但不要把数量写死成产品规则。
「正在查看」与「已选定」必须分开。点击比较项只是查看；主按钮「选这条，准备内容」才确认选择。选择按钮与当前路径相邻，关键风险、重要未知和有依据的停止条件在点击前可见。
将「查看判断依据」「不同情况怎么选」「查看其他方案」「下载路径报告」做成具名入口。详细来源、支持／反面证据、假设、计算、分支触发／停止／恢复条件与条件决策树按需展开，可返回原比较状态。不要默认摆出材料库＋聊天＋工具的专业三栏工作台。
结果区分有依据的估计、假设下的情景测算、暂不可估；缺数据就显示未知或暂不可估，不捏造概率、提升率或装饰图表。
路径报告用真实可下载的本地 HTML 文件，包含依据、风险和条件；下载不改变选定状态。

### 第三页：拿内容使用
打开就能看到所选行动的可用内容；没有有效选择时显示返回选路的空态，不默认塞入成品。设清楚的内容切换、主预览、就近复制／导出和使用前核对区域，不再重复整段诊断。
依据所选路径提供对应的文案、操作步骤或核实清单，不把所有工具堆出来。内容可直接阅读和取用，不能只有「这里将生成内容」。
复制只在浏览器实际成功后提示；失败提供「全选文字」。导出生成真实 TXT 文件；下载只提示已发起，不声称文件已在用户设备落盘。查看、复制、下载均不等于已采用或已执行。
「记录使用情况（选填）」放在内容之后：是否采用、实际执行、观察结果分别记录；未反馈保持未知，不强制完成后才能拿内容。
保留返回路径、带着新情况再分析，以及查看选择记录的入口；记录可在当前页详情中浏览，不新增第四个主页面。前后返回保留草稿，输入或选路变化后，旧结果与旧内容要提示需更新，不能继续假装有效。

## 4. 合成案例与能力边界
用一个明确标注「合成示例」的床底收纳箱案例贯穿三页：商家说短视频有播放，但买家常问床底能否放下；想先弄清问题，不希望立刻增加投放。可以演示「先把适配信息讲清楚」与「先核实买家犹豫原因」的取舍；这只是交互样例，不是已验证的经营建议。
示例提供可读的真实中文内容，不用 lorem ipsum、空卡片或假增长数字。任意自填内容不能直接套用这份预设分析；通过明确的「体验示例」进入合成路径，不能伪装成对真实输入的诊断。
MoneyAI 在正式产品中承担分析、路径与历史决策。在公共页头用一处清楚但不抢眼的状态说明「演示数据，未接通 MoneyAI」，不在每个面板重复免责声明。本地草稿真正写入后才提示已保存，保存失败可重试且不丢输入；未读回不能当空历史，本地记录不能标成 MoneyAI 已保存或已记住。界面有完整、空白、失败和未知状态，但不伪造服务成功。
只做前端与本地状态，不启用云后端、数据库、登录、支付、真实模型、真实商家接口或 Git 同步，不自动发布，不要求上传私人资料。报告和导出只包含必要的合成摘要，不附原始转写、完整问答或材料原件。它不代表现有项目换栈或接入完成。

## 5. 制作与交付
先建立统一字体、间距、颜色、按钮和状态组件，再逐块完成三页及它们之间的点击流程。本次只给一套一致的方向。
不要做营销落地页、复杂后台、满屏 KPI、无限聊天、长 Word 文档式平铺，也不要只给旧段落加边框。
检查首屏能否快速看懂「我在哪里、现在做什么、点哪里继续」；第二页比较和选择、第三页预览和取用不能被标题说明挤到下方。必要信息默认可见，其余信息仍可发现、可返回。
完成后实际检查主流程、返回草稿、查看与选择的区别、复制／下载、错误状态和键盘焦点；给出三页实际运行截图及真实尺寸，目标为 1920×1080，取不到时明确说明。最后简要列出设计 token、组件和模拟能力，供现有项目后续选择性参考。
```
