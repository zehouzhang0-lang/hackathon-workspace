### 2. 本次目标

产出两个文件，均标为“待审草案”，并注明使用的需求版本、资料来源、整理日期和工作起点的 Git 提交；如使用了未提交修改，另行说明：

- `docs/development/CONTRACT_DRAFT.md`：最小跨页信息约定、状态变化、冲突与待确认项。
- `docs/development/TASK_QUEUE_DRAFT.md`：最多五个有边界的后续任务建议，每项说明目标、依赖、允许修改范围、输出、验收与启动条件。

如目标文件已存在，先阅读并保留已确认内容；不得覆盖他人未完成的编辑。以上路径是计划输出，本文不代表文件已生成。

### 3. 数据契约草案至少覆盖

用简洁字段表或示例说明数据含义，不把字段变成要求商家逐项填写的表单，不生成正式 API、数据库表或 TypeScript 类型。

- **问题与依据：**本轮问题、轮次和版本；材料及来源位置；指标的单位、时间、对象、渠道与口径；用户更正、冲突与未知。
- **信息性质：**原始记录、提取结果、商家自述、派生计算、公共参考、情景假设与分析判断分别标识；未知、不适用与零值不混用。
- **补问与版本：**首轮主动补问最多一项，跨页不重置；资料变更后，相关判断、路径、报告和下游材料如何标记为待更新。
- **决策路径：**具体行动、前置条件、投入、预期观察指标及时间范围、风险、停止或调整条件、证据引用与后续分支。
- **预估与不确定性：**区分参数估计区间、预测区间、明确假设下的情景范围及暂不可估；记录适用的数据、方法和限制，不擅自选定算法或填入成功概率。
- **报告与动作：**可下载报告关联路径和资料版本，提供可核对的依据、假设、方法、证据与决策树；请求下载与成功交付区分，下载、选择、采用、执行、反馈是不同事件。没有执行反馈时为未知。第三页只预留必要的交接语义，其交互仍待确认。

下载报告中的“完整依据”指可审计的决策说明，不要求导出模型内部思考过程。关键风险不能只藏在下载文件里。未来订单的预测，也不能被标成该行动带来的增量效果。

必要的示例使用明确标注的模拟或抽象数据。不得把历史演示案例、预编写答案或未来反馈当成本轮商家证据；不需要为了填满契约而编造经营数字。

### 4. 允许与禁止

**允许：**读取上述已登记上下文；整理需求来源与冲突；修改本任务的两个 Markdown 输出，并在 `PROGRESS.md` 追加本任务的实际记录；提出待审方案和未决问题。不改上游已确认决定或其他人的记录。

**不允许：**写应用代码、生成视觉稿、确定技术栈、安装依赖、接入模型或平台账户、读取未授权私密资料、上传商家原件、自动发布或部署。不得把第三页旧建议、具体区间算法、解析或存储能力写成已批准或已实现。

不把下一步拆分建议自动加入正在执行的工作；是否提交和同步文档，遵守仓库约定及本次启动消息的授权范围。

### 5. 可观察的验收

1. 两份输出存在，标题明确是待审草案；已确认要求、设计建议、缺失信息可区分，并能找到来源。
2. 只描述一句问题、没有新材料的情形也有合法表示；未提供的经营指标仍为未知，不要求完整商家档案。
3. 用简短走读说明：口径不一致不能直接计算；证据不足可暂不可估或采用显式假设情景；区间不被伪装成有验证依据的成功概率。
4. 更正一项关键资料后，能指出哪些路径和报告需要更新；报告下载或复制不会把执行状态改成已完成。
5. 第三页只提出待审交接字段，不替用户决定页面布局、反馈流程或长期记忆方案。
6. 后续任务均有清楚依赖与停止点，未获批准的视觉、接口、算法和实现任务不显示为可立即执行。

### 6. 自检、汇报与停止

- 通读文字、相对链接和示例，检查无乱码、无凭据、无真实商家隐私，确认没有把建议写成确认结论。
- 运行适用的仓库检查，例如 `python scripts/verify_demo_content.py` 与 `git diff --check`，记录实际命令、结果和未运行原因；静态检查通过不等于页面、模型或商业效果验证通过。
- 汇报两个输出路径、关键契约选择、需求冲突、待用户确认的少数问题，以及实际验证记录。不要声称页面或接口已经完成。
- **完成后停止。** 等用户审阅，不自动运行任务队列中的任何任务。
