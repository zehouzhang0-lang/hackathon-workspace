# V0.4参考的吸收边界

来源：用户2026-08-28提供的伙伴V0.4交接包。已静态阅读34份业务文件并核对内附版本；本摘要依据用户随后要求“融会贯通已有成果、准备三页开发prompt”整理，供同仓库开发协作。只包含非敏感产品/工程结论，不复制私密原件、完整源码或本机路径。

## 可复用的思想

- 把“优化抖音”变成一个具体、可操作且可观察的经营实验。
- 区分输入与输出、事实与假设；确定性计算不交给文案生成器随意改写。
- 每条动作说明前置条件、投入、风险、观察方式、停止与回滚。
- 数据、规则、UI、接入分开；用合成案例与边界测试验证接口。
- 失败时保持可用内容并明确来源，不冒充真实模型生成。

## 不直接继承

| V0.4现状 | 本次三页的处理 |
| --- | --- |
| 19字段表单/缺数补齐5个指标 | 系统内部可结构化，用户入口仍是一句话或一份材料 |
| 固定阈值选择唯一漏斗断点 | 允许有限分析、资料不足、无可靠路径；不把演示阈值当平台标准 |
| 固定A/B、流程图节点 | 示例可有两条，接口用数组；树展示经营条件，不拿页面步骤当决策树 |
| 质量分和高/中/低置信 | 不等于概率/区间；本轮只做明示假设的情景或不可估 |
| “七个Skill”标签 | 不宣称已执行独立专家；未接入的能力不显示已运行 |
| 结果好坏映射为采用/未采用 | 执行、采用、观察、保存独立建模 |
| 关键词“没变化”就换方案 | 先看是否执行、样本/窗口/口径是否可比，不能先判无效 |
| 每商品一条localStorage记录 | 本轮约定版本化本地历史与真实保存读回，仍不叫远程长期记忆 |
| 深色单页双模式 | 不直接采用；三页独立且统一风格，视觉由用户选择 |
| macOS应用内部启动脚本 | 不执行、不移植为前端前提；利用本机HTML运行环境 |

包内“伙伴A做单轮、主仓库维护UI和第二轮”未对应张泽厚具名角色。当前页面Agent1—3是用户最新提出的新分工，不能与包内伙伴A混同。

包内3个商品案例都是合成且已有订单；旧/新版本数值调整不是执行前后收益。包作者报告模型和测试跑通，本次没有重跑。当前Demo以仓库已可共享的床底收纳箱合成素材为主，不把伙伴原件设为其他对话必须能访问的依赖。

本次吸收的是结构与经验，不是批准一套现成产品，更不构成效果、准确率或真实数据接入证明。
