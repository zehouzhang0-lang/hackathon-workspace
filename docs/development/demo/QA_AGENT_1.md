### 本批重点修补的保存与恢复边界

1. **旧理解 A／当前已更正 B。** 核对区同时显示两者。只有用户打开字段并明确核对 B，才以 B 为本次编辑起点，追加 B→C；保留原始转写、完整更正前缀、fact ID 及原 fact_correction。提交核对打开时的 fact/round/inputVersion 快照，后来再变就拒绝。数组对应或类型不明确时可读地保留冲突并阻止该项保存，不按索引猜值，也不把 B 自动灌入其他字段。
2. **提交成功但回执丢失。** finish 绑定原请求、预期保存版本、材料、逐问与完整输入语境。若保存之后发生其他材料/问题/输入变化，找回旧操作回执不能清 description/context dirty、语音原文，也不自动进入补问或导航。仅相同 draft 不足以当作当前输入已保存。
3. **revision-only 冲突。** 重读当前状态，先用原 ID 和原载荷查幂等回执；确认 session/round/inputVersion、完整输入和问题快照均未变后，才只更新 expectedRevision 重试。commandId、业务 payload 和其中 inputVersion 保持不变。输入有变化仍拒绝，不把旧稿换成新 IV 重放；额外非业务修订造成的旧成功回执保守要求重核对。
4. **导航保存。** 原话、编辑文、来源、更正及其他待保存内容全部成功才返回 true；INPUT_EDIT 成功不能清 voice dirty。识别尚未结束、补问/纠错未保存、跨轮、旧快照或失败时保留草稿并拒绝假成功。
5. **示例／重置／返回。** 新 state 不含 intake 且本页无脏稿时，清理旧理解、绑定、编辑/来源上下文和旧步骤；connect 判空后再恢复。若有脏稿则保留原文及旧轮来源语境，不自动丢弃或重套新轮。补问返回核对后保留未提交文字；同题输入版本改变须再次明确核对，跨轮或另一题不能自动绑定。
